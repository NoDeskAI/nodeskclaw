# NoDeskClaw 产品演示流程

> 创建时间：2026年3月3日
> 预计总时长：15-20 分钟（必演部分约 10 分钟）

## 一、演示前准备

### 1.1 环境准备清单

| 准备项 | 说明 | 状态 |
|--------|------|------|
| Portal 可访问 | 用户门户地址可正常打开 | [ ] |
| Admin 可访问 | 管理后台地址可正常打开 | [ ] |
| 飞书 SSO 可用 | OAuth 应用配置正确，回调地址可达 | [ ] |
| K8s 集群健康 | 至少一个集群状态 healthy，节点 Ready | [ ] |
| LLM Key 已配 | 至少一个实例已配置 LLM Provider 和 Key | [ ] |
| 基因市场有数据 | 预置足够多的基因卡片（不同标签、评分） | [ ] |
| 网络稳定 | SSE 实时功能依赖网络连通性 | [ ] |

### 1.2 预置数据

为了避免演示过程中等待时间过长，建议提前准备：

1. **一个已部署就绪的实例**：用于直接展示实例详情、基因安装、工作区协作等功能，跳过 2-3 分钟的部署等待
2. **一个已配好 Agent 的工作区**：用于直接展示 3D 画布和群聊
3. **基因市场数据**：至少 10+ 个基因（覆盖能力/性格/知识/工具四类标签），2-3 个基因组
4. **一个"全新"飞书测试账号**：用于演示从零开始的首次体验流程（登录 → 组织开通 → 创建实例）

### 1.3 演示设备

- 浏览器：Chrome，提前清除缓存/登录态（新用户流程需要）
- 屏幕分辨率：建议 1920x1080 或更高
- 准备两个浏览器窗口/Profile：一个演示 Portal，一个演示 Admin

## 二、演示结构总览

演示分为两大部分，先用户门户后管理后台，突出「产品价值」优先于「运维能力」。

```
第一部分：用户门户（User Portal） ← 面向普通用户
  ├── Scene 1：登录与组织开通
  ├── Scene 2：创建 AI 实例（核心价值）
  ├── Scene 3：配置大模型
  ├── Scene 4：基因市场（核心差异化）
  ├── Scene 5：3D 协同工作区（视觉亮点）
  └── Scene 6：实例能力管理

第二部分：管理后台（Admin Panel） ← 面向管理员
  ├── Scene 7：Dashboard 总览
  ├── Scene 8：集群管理
  ├── Scene 9：高级部署
  ├── Scene 10：运维监控
  ├── Scene 11：基因运营
  └── Scene 12：企业空间
```

## 三、第一部分 —— 用户门户（约 10 分钟）

### Scene 1：登录与组织开通（约 1 分钟）

**目标**：展示零门槛的企业入驻体验。

| 步骤 | 操作 | 演示要点 |
|------|------|----------|
| 1 | 打开 Portal 首页 | 展示登录页设计 |
| 2 | 点击「飞书登录」 | 一键 SSO，无需填写注册表单 |
| 3 | 在飞书侧完成授权 | 展示授权弹窗 |
| 4 | 回调后进入组织开通页 | 首次登录自动引导 |
| 5 | 填写组织名称、标识符，点击创建 | 30 秒完成企业入驻 |
| 6 | 跳转到工作台首页 | 展示空状态引导 |

**话术参考**：

> 企业成员用飞书一键登录，不需要额外注册任何账号。首次使用会自动引导开通企业组织，30 秒完成入驻。同一飞书租户下的其他成员登录后会自动加入已有组织，无需邀请。

---

### Scene 2：创建 AI 实例（约 2 分钟）

**目标**：展示核心价值 —— 3 分钟一键部署，取代 30 分钟的手动 K8s 操作。

| 步骤 | 操作 | 演示要点 |
|------|------|----------|
| 1 | 进入「实例」页面，点击「创建实例」 | 简洁的创建入口 |
| 2 | 输入实例名称 | 自动生成 slug |
| 3 | 选择规格：轻量 / 标准 / 高性能 | 面向非技术用户的规格描述，屏蔽 K8s 细节 |
| 4 | 点击创建 | 跳转到部署进度页 |
| 5 | 观察 SSE 实时进度 | 进度条逐步推进，每一步状态实时更新 |

部署流水线步骤展示：

```
预检 → 创建命名空间 → 写入配置 → 挂载存储 → 部署容器 → 配置网络 → 设置安全策略 → 等待就绪
```

**话术参考**：

> 传统方式部署一个 OpenClaw 实例，需要手动编写 Deployment、Service、Ingress、PVC 等多个 K8s YAML 文件，还要配置环境变量、网络策略，至少需要 30 分钟且容易出错。
>
> 现在用户只需输入一个名称、选一个规格，平台在后台自动完成全部 K8s 资源编排，并通过 SSE 实时推送每一步的进度。整个过程约 3 分钟。

**注意**：如果演示时间紧张，可以在进度页简要说明后，切到预先部署好的实例继续后续演示。

---

### Scene 3：配置大模型（约 1 分钟）

**目标**：展示安全的 LLM 密钥管理机制。

| 步骤 | 操作 | 演示要点 |
|------|------|----------|
| 1 | 进入实例详情 → 「模型配置」Tab | LLM Provider 选择界面 |
| 2 | 选择 Provider（如 Anthropic / OpenAI） | 展示多 Provider 支持 |
| 3 | 填入 API Key，选择模型 | 组织 Key / 个人 Key 两种模式 |
| 4 | 保存并重启 | 配置即时生效 |

**话术参考**：

> NoDeskClaw 提供两种 LLM Key 管理模式：管理员可以为组织统一配置 Key，也支持员工自带个人 Key。所有请求通过 LLM Proxy 转发，OpenClaw 实例本身不持有真实密钥，保障企业密钥安全。

### Scene 4：基因市场 —— AI 能力进化（约 3 分钟）

**目标**：展示核心差异化功能 —— AI 不是静态工具，而是可进化的数字员工。

#### 4.1 浏览基因市场

| 步骤 | 操作 | 演示要点 |
|------|------|----------|
| 1 | 进入顶栏「基因市场」 | 展示基因卡片列表 |
| 2 | 切换 Tab：基因 / 基因组 / 进化趋势 | 三种维度 |
| 3 | 使用标签筛选（能力/性格/知识/工具） | 精准查找 |
| 4 | 使用搜索和排序（热门/评分/效能/最新） | 多维排序 |
| 5 | 点击一个基因卡片进入详情 | 展示描述、协同推荐、变体列表、效能分 |

#### 4.2 安装基因到实例

| 步骤 | 操作 | 演示要点 |
|------|------|----------|
| 6 | 点击「安装」按钮 | 弹出实例选择弹窗 |
| 7 | 选择目标实例，确认安装 | 一键安装 |
| 8 | 观察学习状态流转 | 如果基因有 meta-learning，展示学习过程 |

#### 4.3 实例基因管理

| 步骤 | 操作 | 演示要点 |
|------|------|----------|
| 9 | 进入实例详情 → 「基因」Tab | 展示已安装基因列表 |
| 10 | 展示基因状态（学习方式、效能分） | 每个基因都有量化的效能评估 |
| 11 | 演示「创造基因」功能（如时间允许） | Agent 自主创造新能力 |

**话术参考**：

> 基因市场是 NoDeskClaw 最核心的差异化。我们用生物进化的隐喻来管理 AI 能力：
>
> - **学习**：给 Agent 安装新基因，它会通过 meta-learning 真正「理解」这个能力，而不是简单的 prompt 拼接
> - **创造**：Agent 在解决实际问题后，可以自主创造新的技能基因，沉淀为企业知识资产
> - **遗忘**：不再需要的能力可以安全卸载
> - **效能评估**：每个基因都有数据驱动的效能评分，帮助企业做能力迭代决策
>
> 员工可以把训练好的优质基因发布到内部市场，其他团队直接安装复用。这就是企业级的知识资产流通。

### Scene 5：3D 协同工作区（约 3 分钟）

**目标**：展示视觉亮点 —— 沉浸式的多 Agent 协作空间。

#### 5.1 创建与进入工作区

| 步骤 | 操作 | 演示要点 |
|------|------|----------|
| 1 | 进入「工作区」页面，创建新工作区 | 填写名称即可 |
| 2 | 进入工作区 | 3D 六边形画布首次加载（视觉冲击） |
| 3 | 切换 3D / 2D 视图 | 两种模式适应不同偏好 |
| 4 | 在画布上平移/缩放 | WASD/方向键平移，+/- 缩放 |

#### 5.2 添加 Agent 并协作

| 步骤 | 操作 | 演示要点 |
|------|------|----------|
| 5 | 点击「添加 Agent」 | 选择已部署的实例加入工位 |
| 6 | 观察 Agent 在六边形工位上出现 | 3D 角色建模，有 idle 动画 |
| 7 | 添加第二个 Agent | 展示多 Agent 场景 |
| 8 | 打开群聊面板 | 发送消息给工作区内所有 Agent |
| 9 | 使用 @ 提及特定 Agent | 定向提问 |
| 10 | 观察 Agent 响应 | Agent 角色动画切换为 working/thinking |

#### 5.3 工作区辅助功能

| 步骤 | 操作 | 演示要点 |
|------|------|----------|
| 11 | 打开黑板 | 展示目标 OKR、任务看板（Todo/Doing/Done/Blocked） |
| 12 | 展示过道系统（如已配置） | 有向信息路由，控制 Agent 间的通信路径 |
| 13 | 展示 Human Hex（如已配置） | 人类节点，支持飞书消息推送 |

**话术参考**：

> 工作区是我们最具辨识度的功能。我们用 Three.js 构建了一个 3D 可视化的协作空间，每个 Agent 占据一个六边形工位，像即时战略游戏一样直观。
>
> 这不是简单的聊天界面。过道系统控制信息的流向，黑板是团队的共享看板，Human Hex 把飞书消息通道也接了进来。用户可以在一个统一的空间里指挥和观察自己的 AI 团队协作。

## 六、常见问题准备（Q&A）

| 问题 | 参考回答 |
|------|----------|
| 支持哪些 K8s 集群？ | 当前支持火山云 VKE，架构上预留了 Cloud Provider 抽象接口，后续可接入 ACK、TKE 等 |
| 数据存储在哪里？ | 平台数据存在火山云 RDS PostgreSQL，实例工作数据存在 NFS 持久卷 |
| 实例之间数据是否隔离？ | 每个实例独立 Namespace、独立 PVC，网络策略隔离 |
| LLM Key 安全吗？ | Key 通过 LLM Proxy 代理转发，实例不持有真实密钥；同时支持组织统一管理和个人自带两种模式 |
| 基因市场的基因质量如何保证？ | 管理员审核机制 + 效能评分系统（数据驱动的量化评估） |
| 支持多少个实例？ | 取决于 K8s 集群资源，平台本身无数量限制 |
| 能否对接内部系统？ | 支持 MCP Server 配置和飞书 Channel，可对接外部工具和消息通道 |
| 多租户怎么实现？ | 组织级隔离，每个组织独立的实例、成员、配额管理 |
