# 部署进度页面与失败清理

## 现状问题

- 点击"开始部署"后，进度条嵌在表单页最底部的一个小 Card 里，不够直观
- 只有一个进度条 + 当前步骤名，无法看到所有 9 个步骤的逐步完成状态
- 部署失败后，K8s namespace 和已创建的资源残留在集群中，需要手动清理

## 方案

### 一、前端：新建独立部署进度页

新增 `claw-buddy-frontend/src/views/Deploy/DeployProgress.vue`，路由 `/deploy/progress/:deployId`。

**页面结构：**

- 顶部：实例名称 + 总进度条
- 中间：**垂直步骤时间线**，展示全部 9 个步骤（`DEPLOY_STEPS`）
  - 已完成步骤：绿色勾 + 步骤名
  - 当前步骤：蓝色旋转图标 + 步骤名
  - 待执行步骤：灰色圆点 + 步骤名
  - 失败步骤：红色叉 + 步骤名 + 错误信息
- 底部结果区：
  - 成功：显示访问地址，提供"查看实例"按钮跳转到实例详情
  - 失败：显示错误原因 + "命名空间已清理"提示 + "返回重新部署"按钮

**数据流：**

1. 从路由参数拿到 `deployId`（以及通过 query 传递 `instanceName`）
2. 立即订阅 SSE `GET /deploy/progress/{deployId}`
3. 前端维护一个 `steps` 数组（长度 = `total_steps`），每收到一个 SSE 事件：
  - `step - 1` 之前的全部标记 `completed`
  - 当前 `step` 标记 `in_progress`
  - 收到 `status=success` 全部标记 `completed`
  - 收到 `status=failed` 当前步骤标记 `failed`

**修改 `Deploy/index.vue`：**

- `handleDeploy` 中拿到 `deploy_id` 后，`router.push` 到 `/deploy/progress/${deployId}?name=${form.name}` 而非停留在当前页
- 移除旧的 SSE 订阅逻辑和 progress Card

### 二、后端：部署失败时清理 namespace

修改 [deploy_service.py](claw-buddy-backend/app/services/deploy_service.py) 的 `execute_deploy_pipeline`：

**两个失败场景都需要清理：**

1. **就绪超时**（`deployment_ready = False`）—— 第 376-388 行附近
2. **异常捕获**（`except Exception`）—— 第 390-406 行附近

**清理逻辑（两处复用同一段）：**

```python
# 清理 K8s namespace（级联删除所有资源）
try:
    await k8s.core.delete_namespace(ctx.namespace)
    logger.info("部署失败，已清理命名空间: %s", ctx.namespace)
except Exception:
    logger.warning("清理命名空间 %s 失败", ctx.namespace)

# 软删除实例 + 级联软删除部署记录
instance.soft_delete()
await db.execute(
    update(DeployRecord)
    .where(DeployRecord.instance_id == ctx.instance_id, DeployRecord.deleted_at.is_(None))
    .values(deleted_at=func.now())
)
```

**SSE 推送增强：** 在失败消息中追加"命名空间已清理"说明，让前端展示。

### 三、路由配置

在 [router/index.ts](claw-buddy-frontend/src/router/index.ts) 添加：

```typescript
{
  path: '/deploy/progress/:deployId',
  name: 'DeployProgress',
  component: () => import('@/views/Deploy/DeployProgress.vue'),
}
```

### 四、后端 DEPLOY_STEPS 暴露（可选但建议）

新增 REST 端点 `GET /deploy/steps` 返回步骤列表，让前端在 SSE 第一条消息到达前就能渲染空步骤骨架。或者前端直接硬编码步骤名（9 个固定步骤），二者均可。我倾向前端通过 SSE 第一条消息的 `total_steps` 初始化步骤数，步骤名随 SSE 逐步填充，这样无需新增 API。
