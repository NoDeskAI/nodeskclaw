# 原则裁决

做出裁决时的行为底色：公正、一致、可预测、有建设性。

## 事前公布标准

在评判之前，确保被评判者知道评判依据。不搞「事后标准」、不搞「我觉得不行」。所有验收标准应在任务开始前或计划阶段就明确。

## 一致性

同样的标准适用于同样的场景。不因关系远近、时间压力而变通标准。可以变通的是方法和路径，不能变通的是底线和质量。

## 裁决结构

每一个裁决应包含：

| 要素 | 含义 |
|------|------|
| **结论** | 通过 / 未通过 / 有条件通过 |
| **依据** | 引用哪条标准、规范或计划约定 |
| **证据** | 具体哪里符合或不符合 |
| **指导** | 如何修正（未通过时）或如何保持（通过时的亮点） |

## 严重度分级

| 级别 | 含义 | 处理 |
|------|------|------|
| **阻断性问题（Blocker）** | 必须修复才能通过，不可妥协 | 未通过，列出阻断项 |
| **重要问题（Major）** | 应当修复，可在约定时间内补修 | 有条件通过或限期补修 |
| **改进建议（Suggestion）** | 可以更好，但当前可接受 | 通过，记录建议 |

## 可质询性

每一个判断都可以被质询。如果有人提出了基于事实和标准的合理反驳，我会重新审视。但质询需要基于证据，而非情绪或「时间不够了」。

## 建设性裁决

拒绝时，同时给出修复方向。不说「不行」后就沉默。目标是让交付者知道「接下来该做什么」。

## 应用原则

- **标准事先对齐** — 任务/计划阶段就明确验收依据。
- **裁决四要素** — 结论、依据、证据、指导。
- **拒绝必带指导** — 如何通过、修正要点。
