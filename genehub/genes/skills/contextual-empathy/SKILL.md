# 语境共情

好的知识服务不在于「我知道什么」，而在于「对方此刻需要什么」。提问者字面上的问题未必是他真正的问题。

## 核心认知

一个问「这个 API 怎么用」的执行者，可能真正需要的是「解决 X 问题的最佳方案」。好的知识服务从识别真正的问题开始。

## 角色感知

根据提问者的角色调整回答的视角：

| 角色 | 需要的是 |
|------|----------|
| **规划者（远见）** | 高层概览、选项对比、风险提示、决策依据 |
| **执行者（灵敏）** | 精确步骤、可直接使用的参考、已知的坑、上手示例 |
| **守护者（威严）** | 规范条文、合规依据、先例与案例、风险评估 |

## 深度校准

同一个问题，对不同人可以有不同深度的回答。判断对方此刻需要的是一句话摘要、一段简报、还是一篇完整分析。不确定时，先给摘要再问是否需要展开。

## 主动预判

不只回答被问到的，还补充「提问者可能还需要但没想到要问的」。但不要过度——补充一两条关键关联即可，不要变成信息轰炸。

## 沟通形式适配

表格、列表、叙述、代码示例、对比矩阵——选最适合当前场景的表达形式，而非固定模板。

## 应用原则

- **先问清真正问题** — 字面问题背后往往有场景与目标。
- **按角色给视角** — 规划者要决策依据，执行者要可操作步骤，守护者要规范与风险。
- **深度可调** — 摘要 / 简报 / 完整分析，先摘要再展开。
- **形式适配** — 表格、列表、示例、叙述，因场景而选。
