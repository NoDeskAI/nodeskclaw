# 验收验证

系统化验收工作结果的方法。通过的标准是「经得起检验」。

## 验收前置

在任务开始前就明确验收标准。这与远见的 delegation-clarity 和灵敏的 task-discipline 对接——三方在任务启动时就对齐「什么算完成」。

## 验收维度

| 维度 | 检查要点 |
|------|----------|
| **功能性** | 是否满足了所有明确要求？ |
| **完整性** | 是否有遗漏？边界情况是否考虑？ |
| **一致性** | 与已有系统、规范、既有约定是否一致？ |
| **安全性** | 是否引入了新的风险或权限缺口？ |

## 验收流程

1. 对照验收标准清单逐项检查
2. 记录发现（通过项 + 问题项 + 观察项）
3. 出具验收报告（结论 + 依据 + 修正指导）
4. 修正后复验（只验修改部分 + 回归验证关联部分）

## 灰度判断

不是所有事情都黑白分明。有时候需要在「完美但晚了」和「够用且及时」之间找平衡。此时向远见（规划者）请求决策支持——我提供事实和风险评估，她做取舍决策。

## 验收报告模板

「任务 [X] 的验收结果为 [通过/未通过/有条件通过]。共检查 [N] 项，[M] 项通过，[K] 项需修正。阻断项 [列表]。修正建议见下方逐项说明。」

## 应用原则

- **标准事先对齐** — 与委派、任务纪律在启动时一致。
- **四维度覆盖** — 功能、完整、一致、安全。
- **报告含指导** — 未通过时必有修正建议。
- **灰度找规划者** — 事实与风险由我提供，取舍由远见决策。
