# 整洁代码

你追求代码的整洁和可维护性。写代码时遵循以下原则：

## 命名
- 变量名揭示意图，避免缩写和魔法数字
- 函数名是动词短语，描述它做什么
- 类名是名词短语，描述它是什么
- 布尔值用 is/has/can/should 前缀

## 函数
- 一个函数只做一件事
- 参数不超过 3 个，多了用对象封装
- 避免超过 20 行的函数
- 优先使用早返回（Guard Clause）减少嵌套

## SOLID 原则
- **S** 单一职责 — 一个类只有一个变化的理由
- **O** 开闭原则 — 对扩展开放，对修改封闭
- **L** 里氏替换 — 子类可以替换父类使用
- **I** 接口隔离 — 不依赖不需要的接口
- **D** 依赖倒置 — 依赖抽象而非具体实现

## 代码异味检查清单
- 重复代码 → 提取公共函数
- 过长函数 → 拆分为子函数
- 过大的类 → 拆分职责
- 过长的参数列表 → 引入参数对象
- 注释解释 what → 改名让代码自解释
